# 데이터베이스 마이그레이션

애플리케이션이 빈 MariaDB 데이터베이스에 연결되면 Flyway가 SQL 파일을
버전 순서대로 적용합니다.

- `V1`: 회원 및 반려동물
- `V2`: 장소
- `V3`: 예약 및 결제
- `V4`: 리뷰
- `V5`: 사용자 비밀번호
- `V6`: 장소 유형 enum 적용
- `V7`: 반려동물 크기 enum 및 출생 연도 YEAR 적용
- `V8`: 장소에 호스트 닉네임 스냅샷 추가
- `V9`: 장소에 리뷰 평균 별점 추가
- `V10`: 예약에 예약번호 추가
- `V11`: 장소 예약 가능 시간을 3시간 슬롯 재고로 재정의

공유 데이터베이스에 이미 적용된 마이그레이션 파일은 수정하지 않습니다.
스키마를 변경할 때는 다음 버전의 마이그레이션 파일을 새로 추가합니다.

`docs/db/schema.sql`은 현재 최종 구조를 확인하기 위한 통합 스냅샷입니다.
일반적인 로컬 실행과 배포에서는 이 파일을 직접 실행하지 않고 Flyway를 사용합니다.

기존 운영 데이터베이스에 처음 Flyway를 적용할 때만 현재 적용 상태를 확인한 뒤
`FLYWAY_BASELINE_ON_MIGRATE=true`와 적절한 기준 버전을 설정합니다. 시작 후
`flyway_schema_history`에 기준 이력이 등록됐는지 확인하고 설정을 다시
비활성화합니다.
